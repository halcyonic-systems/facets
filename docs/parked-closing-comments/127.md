**Part of this was solved differently, and better.** `docs/lean-provenance.md` plus `docs/lean-manifest.json` now anchor every SSF citation **by declaration name and Lean kind**, generated rather than hand-written, with Gate A resolving them at the pin and Gate B against SSF HEAD. That is symbol-anchoring for exactly the citations where a line number is, in `theory-fidelity.md`'s own phrase, "a coincidence with a timestamp" — the ones that cross a repo boundary. **Gate B failing is the natural trigger** for that half: it is the moment a citation demonstrably stopped resolving.

**What is not covered is the in-repo half**: `docs/*.md` citing `crates/**/*.rs` by `file:line`. Those still rot silently, and this issue's own example — `validate_mode` cited at 123–146, now ~254 — is still live. The ledger keeps it, and records a smaller candidate than the issue proposed: a `path.rs:NNN` line-number citation in a LIVE doc could simply be **banned in favour of a symbol name**, checkable with the same machinery `doc_lint` now uses for the status carrier. That is a candidate, not a decision.

**The issue-link-liveness half** is untouched as an automated check; the #80 sweep in the same change is the manual version of it, done by hand this time.
